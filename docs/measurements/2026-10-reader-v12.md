# V12 mandatory draft review: closed quality failure and stopping decision

A second same-model review did not produce dependable personal/project continuation under the fixed
shared budget. The freshly authored blinded panel gave the one-call source-block baseline 5/16
strict
useful answers and the reviewed candidate 3/16, with 5 and 6 critical-error candidates respectively.
The candidate fails the prospectively fixed >=14/16, zero-critical, no-worse-than-baseline gate.
No reader integration, real-memory migration or merge is justified. The preregistered stopping rule
now applies: stop adding memory mechanisms and shopping for models or easier panels; identify the
reader capabilities still missing and the deterministic guarantees already available.

[Machine-readable results and complete measured costs](2026-10-reader-v12-summary.json) retain the
frozen grading hash, gate, paired outcomes and draft-damage denominators. This report publishes no
private gold or reusable closed scenarios.

## Fixed method and admission

V12 tests one bounded hypothesis: a mandatory second semantic review of an unchanged generated
draft, using the same `ornith15` model on the authorized LAN server. The recovered V9 source-block
baseline receives one generation with 1024 output tokens reserved. Candidate draft and final review
receive 512 each; unused output reserve cannot transfer. Each complete slot has 4096 tokens:
summed actual counted inputs <=3008, reserved outputs 1024, safety 64. Both arms receive the entire
canonical authorized source history and original query. The second pass receives those again plus
the exact rendered draft in an explicitly untrusted wrapper. There is no semantic chooser, retry,
pruning, fallback, alternative model, or replacement answer. Only the final query/answer pair enters
a new session through full-basis revalidation and atomic persistence; drafts are evaluation
artifacts.

The total generation-body bound is 49152 bytes, final bound 16384 UTF-8 bytes. Physical metadata,
formatting, tokenizer and generation requests are individually bounded and charged. Generation has
a hard 60-second limit; baseline/candidate inclusive slot limits are 90/165 seconds. Public/closed
phase limits are 900/5400 seconds. Resource observations bound reclaimable RAM, process peak,
retained bytes and physical responses, with bounded waits and a stop latch. No user applications
were killed, model installed, paid API used, security setting changed, or real memory submitted.
Gold remained local and was never part of model requests.

Before calls, 63 offline tests passed, including 17 grading-contract proofs, with independent
runtime/export review. A frozen 91-entry inventory bound executable code, production Python
sources, procedures,
environment and public inputs. Public protocol admission passed 4/4 persisted finals, with six
opaque draft/final artifacts and independent actual-request/count/persistence audit. This was a
mechanical admission gate, not a public quality score or basis for prompt tuning.

Only then did a fresh independent author create eight new stories with two checkpoints each:
40 events, six personal/two project stories, four EN/four RU stories, two correction chains and two
owner-matched unrelated-scope forget operations. The author did not receive methods, prompts,
public outputs or prior scores. A distinct fresh grader received only frozen gold, original queries,
authorized canonical sources and 48 opaque artifacts. Roles, cost and methods were withheld.
The three artifacts per case are individually graded against the same criteria; the candidate final
is causally dependent on its draft. Output style can partly reveal methods, so perfect blinding is
not claimed. All judgments were frozen before role unmasking; no rescoring occurred.

Independent closed export audit passed all 32 persisted finals plus 16 drafts, native counts,
actual wire/draft bindings, source delivery, complete SQLite footprints and phase/resource checks.
All 91 inventory entries stayed unchanged. All cases remain in the denominator.

## Reader bottleneck and minimum capabilities

Complete sources were delivered, yet current replies or approvals were sometimes replaced by older
pending states. A reported prior fit check was treated as unreported. A private intent was turned
back into indecision; absence of publication permission was used to assert nothing had been posted.
Usable drafts also lost required status or material constraints. Valid source IDs were frequently
attached to a different claim than the cited event supports. These are post-freeze diagnoses of
provided-source reading and artifact construction, not evidence that a larger memory graph is
needed.

A suitable reader must reliably produce the actual requested draft, plan or handoff while retaining
all material current constraints. It must distinguish corrected history from active facts; ability
from commitment; reported progress from verified progress; unknown from absent or undone; drafts
from existing artifacts; and proposals from facts, permission or execution. It must handle these
relations in both English and Russian, preserve unresolved details without making continuation
useless, and place source IDs beside claims those sources support in the correct scope/time/actor.
Creative suggestions and wording should remain visibly proposed, without unsupported suitability
claims. Current prohibitions must survive; historical permission must not become current permission.

The deployment requirement remains a genuinely fresh frozen blinded continuation evaluation meeting
>=14/16 strict useful answers, zero critical errors, and no worse than its equal-budget baseline,
followed by reviewed production integration, regressions and another fresh validation. CI alone
cannot substitute for that requirement. V12 did not reach the first step. Its result identifies a
reader capability limit under this fixed method, not a universal impossibility of local models.

## Deterministic Morgan guarantees and their limits

These references describe production head `5be453c`, under the `morgan_brain/` directory:

- `memory/gate.py:180` and `memory/evidence.py:104` enforce attributed owner/project evidence scope;
  owner attribution is explicitly not authentication (`memory/gate.py:191`). Single-record `get`
  checks owner, so project-scoped callers must additionally enforce project or use evidence.
- `memory/revisions.py:119` validates same-scope chronological correction parents;
  `memory/revisions.py:166` computes whole-note active state at a cutoff. It supplies lifecycle
  metadata, not semantic clause merging. `memory/store/temporal.py:344` enforces exact half-open
  fact intervals. `memory/module.py:913` and `:950` use one cutoff for context show/list.
- `memory/module.py:1074` erases registered project stores and advances erasure generation;
  `:394` and `:402` reject invalidated in-flight turns. Erasure covers these database stores,
  not already exported artifacts, external model inputs, external copies or retained backups.
  Natural-language permission revocation still requires correct reading.
- `memory/module.py:338` requires matching two-event/two-history turns; `:403` enforces fresh
  sessions when requested; `:416` revalidates a supplied complete original basis. Both events and
  history commit together under a write transaction. These optional guarantees require callers
  to supply the full basis and request freshness; they are not automatic for every unrelated call.
- `app/strict_context.py:396` validates structural source support, and
  `memory/working_context.py:166` validates current exact spans. Neither proves semantic entailment.
  Working-context model selections/progress remain explicitly unverified (`:47`, `:49`).
- `providers/llama_strict.py:133` and `:322` reject tool messages/tool calls in this strict path.
  This prevents that path executing a returned tool action; prose claiming something was sent,
  booked or verified can still be false. Network authentication is a separate control.

Storage, lifecycle, attribution and transaction guarantees are valuable foundations. More derived
fields, locators or an extra same-model pass did not establish the missing semantic capabilities in
these bounded panels. The practical stopping decision is to retain the reviewed correctness fix and
existing safeguards, publish the failure, and defer autonomous personal-memory readiness until the
reader clears the capability gate. No new model installation or real-memory migration is proposed.
