# Frozen synthetic continuation comparison V4

The experimental acceptance gate failed. This result does not approve merge,
deployment or live-memory migration of the optional working-context prototype.

Eight fresh synthetic stories supplied sixteen cross-session checkpoints: English
and Russian, personal and project work, old constraints, changed choices, ambiguous
people, revoked contact permission and source-ID requests. Grading used masked arm
labels; the independent grader authored the rubric, so this was not fully blind.
All unavailable answers stayed in the denominator. Fixture-linked revision coverage
was zero; linked revision behavior was checked separately offline.

| Method | Useful / 16 | Critical-error slots | Citation-error slots | Persisted / 16 |
| --- | --- | --- | --- | --- |
| Working view | 0 | 7 | 6 | 9 |
| Complete current-source JSON | 1 | 11 | 10 | 16 |
| Lossless fixed-column source packet | 3 | 8 | 8 | 14 |

Citation errors mean missing, insufficient or unsupported citations; no invented
event IDs were identified. Useful drafts may introduce proposed wording or timing.
The rubric distinguished those proposals from unsupported assertions of existing
facts, identity, capability or permission. These strict synthetic scores are not
an estimate of general conversational usefulness.

All thirty-six physical attempts for the two complete-source methods delivered
every necessary rubric ID. A read-only receipt audit verified actual wire messages
against counted requests and isolated database bodies, reported authors, scope,
timestamps and chronological order. Complete delivery therefore did not eliminate
reader failures. This audit did not test alternative ordering as a causal factor.

Whole-template input counts across the same sixteen logical checkpoints were
15,729 tokens for expanded JSON and 14,069 for fixed columns: 10.55% fewer input
tokens. This paired count excludes generated output, retries and maintenance and
does not establish lower total realized cost or an improvement in usefulness.

The complete run took 1,405.13 seconds, with 204 physical HTTP attempts including
135 counting requests, 68 physical generation attempts and fourteen unknown-usage
attempts. Known usage was 43,086 input and 17,233 output tokens. Unknown usage was
excluded from known totals, never treated as zero. Resource retries were bounded
to transport failures, with no semantic retries. Only the working-view arm used
model maintenance. Each arm used isolated storage and fresh continuation history;
storage used the deterministic hash embedder, so this run measured no LAN embedding
efficiency. No actions were executed and no live memory was touched.

The measured source was `4b1be8396dfecb0cd67b29526581e21fc2a7a36e`, before subsequent
formatting and proposal-integrity fixes. Those fixes are not retrospectively
covered by this experiment. Frozen fixtures, failures, requests and receipts remain
unchanged in the evaluation workspace.

The next general hypothesis concerns reader behavior rather than a new memory
architecture: associate source-dependent statements with checked quotations while
separating explicitly proposed draft choices and unresolved details. Existing tools
offer relevant patterns: [LangExtract](https://github.com/google/langextract) aligns
extractions to source spans, and the [Hermes grounded-citations workflow](https://github.com/NousResearch/hermes-agent/blob/main/skills/research/grounded-citations/SKILL.md)
uses a citation ledger with literal evidence checks. Neither technique proves that
a paraphrased claim follows from its quote. No external code was copied or installed;
any candidate must be preregistered and tested on genuinely fresh cases.
