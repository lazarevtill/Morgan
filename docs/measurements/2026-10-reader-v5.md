# Frozen concise-reader continuation experiment V5

This is a reader-instruction experiment on complete bounded current sources. It
does not measure compact working-view maintenance, retrieval quality or always-on
deployment. The earlier V4 strict result remains four useful outputs out of
forty-eight; its later component audit did not change those scores.

Only the first system instruction changed: the existing continuation reader versus
a concise solution-first instruction. The latter asks for the actual requested
draft/answer first, preserves current choices and older still-valid constraints,
and distinguishes proposed wording from assertions of identity, capability,
permission and completion. Both receive identical chronological lossless source
packets, current queries and system/user/user roles, using the unchanged
single-string TextResult schema. No external code was copied or installed.

The freeze preceded public execution and independent private authorship. It bound
73 production Python files at `8a253588e45cc86dbdca230fcd8815490ef7a267`, six harness
files, the preregistration and public fixture. Twenty offline tests passed, including
transport backoff, Unicode/escaping, linked corrections, revocation, input limits,
fresh history and failed-output atomicity. The initial freeze SHA256 is
`f0f4cea3cefecaecef30aec87be67497d2fdb03be2638372cd8b86b460618337`.

Each request permits 3,008 exact whole-template input tokens, 1,024 output and a
64-token reserve within the experiment's 4,096-token budget, with a 49,152-byte
model/messages/schema envelope. Transport alone permits three attempts with
2/8-second backoff; semantic, format and token failures receive no retry.

The unchanged LAN alias ornith15 reported 35.505 billion parameters, Q6_K and
262,144 context capacity; its name does not establish a 15-billion model size.
Actual requests use temperature zero, seed 42 and thinking disabled. This metadata
is not an immutable weight-file digest or proof of exclusive backend ownership.
Read-only server metadata inspection followed the official
[llama.cpp server documentation](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md).
No model, service, installation or live memory changed.

The four-slot public diagnostic completed in 49.515 seconds. Both English reminders
were useful. Russian baseline asserted purchase-not-done despite unknown status;
Russian concise was rejected at finish_reason length with 1,024 output tokens,
no tool calls and no partial persistence. Its rejected tokens remain charged:
1,764 input and 1,274 output across four chats, eight counter calls and one metadata
call. No public-result prompt tuning followed.

The independently authored fresh closed panel has eight stories and sixteen
cross-session checkpoints: six general personal-memory stories, two optional
project drafts, four English/four Russian, seventy-four events, four explicit
revision links and two unrelated-project erasures. It includes current preferences,
people, reported versus verified status, permission changes, retained constraints,
unknown details and usable local drafts. It requires neither imaginary execution
nor reconstruction of unseen earlier text, and no arbitrary citation quota on
new creative wording. Gold stayed separate from runner/model input. Grading masks
arm names, system instruction and timing but includes actual delivered sources;
author-grader overlap is disclosed, so the study is not fully blind.

The preregistered acceptance gate failed. Both readers produced seven strict useful
continuations out of sixteen. Concise had two critical-error slots, existing reader
three. Four paired checkpoints passed with both, three with concise alone, three
with existing reader alone, six with neither. The instruction change did not show
a paired strict-usefulness advantage and does not approve merge or deployment.

The independent all-output component audit found fourteen strict useful answers,
five useful requested components with critical assertions, seven partial answers
missing material requirements, four useful cores failing citations only and two
cores sensitive to historical-completeness expectations. These are separate
descriptions, not relaxed strict scores. Unlike V4, V5 contains citation-only
failures; source-presence and semantic entailment were checked separately.

Material failures include substituting an unspecified reference for a recorded
parameter, omitting a separately requested question draft, unsupported assertions
that a purchase/publication/draft had not happened, and unrecorded contact history.
Abbreviated source aliases did not satisfy requests for actual delivered event IDs.
The grader explicitly disclosed sensitivities around unasked historical reasons
or inventories and conversational presuppositions in proposed greetings; future
draft wording was accepted when it did not invent prior events. Gold and strict
judgments were frozen before unmasking and were not changed for those sensitivities.

The closed run completed all thirty-two scheduled outputs with persistence and no
retries or unknown usage in 244.865 seconds. Source/runtime hashes remained frozen.
Each arm used isolated hash-embedding storage and fresh checkpoint forks/history;
outputs did not become later source evidence. Thirty-two actual wire/ledger/database
joins verified exact source body, author, scope, time/order and all current primary
sources, including revision resolution; sixteen paired source/query payloads match.
Forgotten-project memories were absent from both arm databases and all continuation
inputs. Synthetic pre-erasure audit snapshots remain; this is not secure disk erasure.

Closed total: 26,376 input/8,241 output tokens, including 5,008 cached input tokens,
97 HTTP calls (32 chats, 64 counters, one metadata), 84 database files occupying
50,339,840 bytes. At the cost-audit snapshot, the two arm directories total

Later read-only database audits created transient SQLite sidecars, not included in
that recorded storage snapshot; the subsequent sidecar size was 1,179,648 bytes.
Startup metadata is charged once; no shared model maintenance
or LAN embedding calls occurred. Full wall includes ingestion, lookup, snapshots,
generation and persistence. Local CPU/energy and server load were not separately
instrumented; storage includes disposable evaluation forks, not steady-state memory.
Four earlier no-memory controls add 490 input/190 output tokens separately. Public
diagnostic and those controls are not hidden per-arm work. These are measured
request/storage costs, not a monetary or general efficiency claim.

The protocol fixes acceptance at at least fourteen useful checkpoints out of
sixteen for concise, zero critical fact/identity/capability/permission/action errors,
and paired usefulness no worse than baseline. Component usefulness and rubric
sensitivities are reported separately. A reader-screen pass would not establish
compact-memory quality, installation readiness or permission to merge PR59.

The small paired panel and author-grader overlap limit generalization. V4 and V5
use different freshly authored cases, so their score difference is not a causal
reader improvement estimate. The paired V5 arms isolate only the frozen instruction
under this backend, complete-source input and budget. Server cache/load and fixed
per-checkpoint order are recorded conditions, not separately randomized causes.

Evidence remains in the evaluation workspace: initial and bound freezes, separate
private fixture/gold hashes, masked grading packet, physical HTTP receipts, source
and erasure audits, and per-arm cost reconciliation. Frozen failures and criteria
are preserved; the panel is not reused for private instruction tuning.

Additional primary GitHub research identifies reusable organization patterns rather
than a replacement stack. The sanitized [Ezra memory snapshot](https://github.com/letta-ai/ezra-memory)
uses small pinned durable context, links into detailed references loaded on demand,
and separate per-user records; it explicitly is an occasional example, not current
product documentation. [Letta memory blocks](https://docs.letta.com/v1-sdk/memory/memory-blocks)
support shared and read-only blocks. The archived
[LettaBot configuration](https://github.com/letta-ai/lettabot/blob/main/docs/configuration.md)
documents Git-backed memory files and headless sync-conflict limitations. These
are patterns for durable organization and recovery, not semantic correctness proof.
No Ezra content/code or external implementation was copied into Morgan.

The current [Mem0 README](https://github.com/mem0ai/mem0) describes ADD-only extraction,
equal weighting of agent-confirmed facts and temporally aware retrieval. Its headline
benchmarks explicitly include proprietary managed-platform optimizations unavailable
in the open-source SDK. Those numbers therefore do not establish Morgan continuation
quality. For this user's goal, adapting a compact reference index with scoped source
recovery is a plausible future design inference; it must retain explicit corrections,
reported/verified status and revocation checks and receive a new independent study.
This research does not change the frozen V5 reader or authorize a new installation.
