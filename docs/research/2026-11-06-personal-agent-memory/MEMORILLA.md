# Memorilla и Morgan: проверка применимости

Проверено 6 ноября 2026 года. Решение: не внедрять Memorilla в текущий пилот.
Полностью прочитан текст v3, включая приложения A–G и таблицы; изучены публичные
реализации memory module, injection, serving и инструкции обучения. Результаты
авторов не воспроизводились и не выдаются за измерения Morgan.

## Статья: метод, результаты, ограничения

[Memorilla: Latent Semantic Memory for LLMs](https://arxiv.org/abs/2610.21375)
опубликована 15 октября; v2 — 27 октября, v3 — 3 ноября 2026 года.

Замороженный Qwen3-Embedding-4B кодирует документы; обучаемый модуль (194,1 млн
параметров) формирует 16 зависящих от вопроса векторов для замороженного Qwen3-8B.
Обучение включает 1,98 млн примеров парафраза, 1,34 млн смешанных примеров и
дообучение на целевых задачах; персонализация получает дополнительную специализацию.

| Проверка авторов | Memorilla | Сравнение |
| --- | ---: | ---: |
| FactKG accuracy | 84,33% | полный контекст 80,43% |
| PMv2 SA | 44,60 | xRAG 30,90 |
| PV4 SA | 66,65 | MemoRAG 67,88 |
| PubMedQA accuracy | 59% | LLMLingua-2 69% |
| TextWorld avg@3 | 24,2% | полная история 18,6% |

SA оценивает ближайший вариант ответа по embeddings; PV4 синтетический.
Среднее разных метрик не является общей точностью. Сжатие считает только документы,
не весь запрос. Измерение 0,739 против 19,932 секунды относится к H100, 512 документам
и full-context baseline, не RAG. TextWorld сохраняет текстовую историю во всех
условиях; 40 тестовых prompts соответствуют 30 уникальным играм. Это не испытание
непрерывной работы. Точные детали могут теряться; гибрид с retrieval показан как
oracle upper bound, а не готовая система. Перенос на Granite и русский пилот не проверен.
[Полный текст, таблицы 5, 11, 14, 15 и приложения D–G](https://arxiv.org/html/2610.21375v3).

## Проверка опубликованного кода

Зафиксирована ревизия
[`d8f18891a50bf33c18f04fe5167c22f51e58c9cd`](https://github.com/snap-stanford/memorilla/tree/d8f18891a50bf33c18f04fe5167c22f51e58c9cd),
коммит от 6 ноября 2026, 00:18:39 UTC. Код сохранён, но не установлен и не исполнен.

- `memorilla/memory.py`: query-conditioned cross-attention и projection в размерность
  входа декодера. Это вычисляемый обученный reader, а не база сообщений.
- `memorilla/llm.py`: `inject_memory` заменяет embeddings зарезервированных позиций;
  Hugging Face получает `inputs_embeds`.
- `memorilla/vllm.py`: генератор получает `prompt_embeds`. Передача строкового
  `<|memory|>` обычному chat endpoint не воспроизводит этот механизм.
- README требует Linux/CUDA/Python 3.11; опубликованный quickstart рассчитан на GPU
  80 GB и загрузку около 25 GB моделей. Это требование поддержанного рецепта,
  не доказательство невозможности любого будущего порта на Mac.
- RL требует отдельного SkyRL fork. README описывает query как mean embedding,
  тогда как приложение G различает обычные и длинные игры. Для точной репликации
  потребуется сверять закреплённый fork и конфигурацию, а не только README.

[Исходники и инструкции на проверенной ревизии](https://github.com/snap-stanford/memorilla/tree/d8f18891a50bf33c18f04fe5167c22f51e58c9cd).

## Сопоставление с фактическим Morgan

Проверен main `0f544b24a3a62782ad126d904fe6998020de1090` (PR #115).
Следующая оценка — инженерный вывод по коду Morgan, не результат статьи.

| Требование персонального агента | Текущее устройство Morgan | Вывод для Memorilla |
| --- | --- | --- |
| Независимая долговечная память | SQLite, MemoryGate, provenance, FTS и vectors | Сохранить как источник истины; латентный reader возможен лишь поверх неё |
| Смена модели/harness | Текстовые CLI/MCP/API; fingerprint embedding space | Замороженный decoder ещё не означает переносимость обученной projection на другую модель |
| Точная история поручения | Явные revisions, подтверждение, текущий task ID | Сжатое представление не должно выбирать полномочия или подменять проверку версии |
| Общий аккаунт | Неизвестный автор экспорта не становится владельцем | Персонализация не должна превращать косвенный намёк в подтверждённый личный факт |
| Проверяемый ответ | Поиск источника сохраняет цитату и текущее состояние | Нужен отдельный точный путь evidence даже при будущем semantic reader |
| Ограниченный локальный inference | Granite GGUF, llama-server, приватный Unix socket | В текущем адаптере нет входа для soft memory tokens |
| Остановка и восстановление | STOP, expiry, receipts, конечные попытки | Это обязанности runtime; статья не заменяет их |

Проверенные участки: `morgan_brain/model_cycle.py::ModelSession.select`,
`providers/note_probe.py::propose_chat`, `memory/gate.py`, `memory/fingerprint.py`,
`owner_input.py`, `owner_search.py`, а также `docs/ARCHITECTURE.md`.
`select` читает одну заметку и возвращает выбранные строки; это ещё не универсальный
диалоговый агент, который сопоставляет свободное сообщение со всеми текущими задачами.

## Почему сейчас нет эксперимента и изменения кода

Не найдено нового переносимого изменения, для которого текущая среда позволяет
проверить именно заявленный механизм. Установка Memorilla означала бы замену
inference stack, загрузку других моделей и отдельную проверку обучения/совместимости.
Одноразовый тест сокращённого текстового промпта на Granite проверял бы другую
гипотезу и не подтвердил бы эффективность латентной памяти.

Полезный принцип — формировать контекст под вопрос, сохраняя первичные данные —
уже присутствует в query-dependent recall Morgan. Новая гипотеза для будущего:
дополнительный обученный reader может помочь обобщать большой архив. Пока не
измерены выигрыш и цена, это исследовательское направление, а не задача миграции.
Никаких значений ускорения или улучшения качества для Morgan здесь не заявляется.

Если появится совместимый локальный backend и достаточно большой разрешённый
архив, проверку следует начать отдельно от пилота: один decoder, одинаковые
вопросы/выходные лимиты; контроль — действующий retrieval, кандидат — латентный
reader с точными цитатами. Набор фиксируется заранее и включает RU/EN, изменение
срока, отмену, чужого автора, одинаковые названия, отсутствие ответа и забытые
записи. Метрики: точность текущего состояния, precision/recall задач, ложные
изменения, корректность источников, утечки scope, latency и память. Нулевые
ложные изменения и утечки обязательны; улучшение на одном примере недостаточно.
Этот протокол не выполнялся и не является обещанием положительного результата.

## Независимая проверка текущего пилота

До получения статьи выполнен отдельный ограниченный аудит, не эксперимент Memorilla:
12 новых синтетических RU/EN заметок, неизменный production prompt, один прогон.
Результат: 12/12 точных наборов строк, TP=6, FP=0, FN=0; медиана запроса 5,057 с.
Отдельно пройдены 12 сценариев состояния: revisions, completion, stale parent,
STOP, expiry, replay и forget. Маленький набор не доказывает production quality
или понимание межсессионного контекста. Ранее отвергнутый update-кандидат с
18/30 точных ответов и 10 FP этим результатом не «исправлен».

Полные локальные материалы: `validation/current-task-audit/REPORT.md`,
`protocol.json`, `cases.json`, `results.json`, `summary.json`, `state-results.json`.
Корпус SHA256: `1946c6e2f1adbceef15e2dec66379a39f39a8940118b4834848acc30442ac3c3`.

## Архив и влияние на пилот

Локально в `validation/memorilla-review/` сохранены `paper.pdf`, `paper.html`,
текстовая выгрузка, `code.tar.gz`, распакованный код и `manifest.json` с SHA256.
PDF/HTML закреплены на v3. В Git публикуется только этот разбор; личные данные,
секреты и содержимое живой памяти в него не включены.

В ходе разбора runtime, данные, STOP и срок пилота не менялись, модели не запускались.
Пилот остаётся ограниченным исходным сроком; статья не делает его работающим во сне
Mac или доступным с телефона. Дополнительных расходов и credentials нет.
