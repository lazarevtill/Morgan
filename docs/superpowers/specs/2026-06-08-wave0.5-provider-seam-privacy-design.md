# Wave 0.5 — Provider Seam + Privacy Foundation — Design

**Date:** 2026-06-08 · **Status:** Approved (from decisions) · **Branch:** `feat/wave0.5-provider-privacy`
**Decisions:** [platform ADR](2026-06-08-platform-architecture-decision.md) · [self-learning ADR](2026-06-08-self-learning-decision.md)

## Goal
Make the model layer truly **provider-agnostic** behind typed seams (closing the gap that
`LLMClient`/`Embedder` don't exist — Phase 1 uses a concrete `OllamaLLMClient`), and land the
**privacy foundation** (encryption, data classification, reversible egress redaction) plus the
future-proofing prerequisites (`schema_version` on events) and a local **MLflow** scaffold behind a
seam. Ends green (pytest + ruff + mypy-strict), provider-swappable, with a redaction completeness test.

Built in three increments, each green & committed:
- **A. Provider seam** (core — unblocks everything)
- **B. Privacy foundation** (encryption + classification + egress redaction)
- **C. Future-proofing + MLflow scaffold** (`schema_version`, MLflow behind `Optimizer`/`Registry` seam)

## A. Provider seam

New package `morgan_brain/providers/` + three seams in `morgan_brain/interfaces/`:

```
interfaces/llm.py        ChatClient   : async agenerate(messages, *, tools?, response_format?, ...) -> ChatResult
                                        astream(...) -> AsyncIterator[StreamDelta]
interfaces/embedding.py  Embedder     : async aembed(texts) -> list[list[float]]   (replaces modules/memory/indexing Embedder)
interfaces/rerank.py     Reranker     : async arerank(query, docs) -> list[Scored]
providers/
  wire.py            ChatMessage, ToolSpec, ChatResult, StreamDelta(text_delta|tool_call_delta|usage|finish)  (OpenAI-shaped)
  capability.py      CapabilityDescriptor + registry (vendored pricing JSON as data) + startup probe + YAML override
  router.py          RoleRouter: role {fast,strong,vision,long_context,embedding,rerank} -> ordered bindings; capability-gated select
  structured.py      structured-output ladder: native json_schema/grammar -> tool-as-schema -> prompted-json -> Pydantic validate + bounded re-ask
  resilience.py      jittered backoff (SDK retries OFF) + role-level fallback; emits LLM_FALLBACK event
  adapters/
    openai_compat.py OpenAICompatAdapter (official `openai` SDK, configurable base_url) — covers Ollama /v1, vLLM, llama.cpp, LM Studio, OpenRouter
    ollama.py        OllamaAdapter (thin subclass setting base_url + Ollama capability quirks, e.g. context cap)
    fake.py          FakeChatClient/FakeEmbedder for tests (deterministic)
  factory.py         build providers + router from Settings; one place provider config lives
```

**Key contracts**
- `ChatClient.agenerate(messages, *, model: str, tools=None, response_format=None)` — `model` is a
  concrete id; callers normally go through `RoleRouter.client_for("strong")` which returns a bound
  client+model. The `Reasoner` asks for a **role**, never a provider/model.
- `CapabilityDescriptor(provider, model, context_window, max_output, supports_tools,
  supports_parallel_tools, json_mode, supports_grammar, supports_vision, embedding_dim, cost_in,
  cost_out)`. Seeded from `providers/data/model_capabilities.json` (vendored), `MORGAN_MODELS` YAML
  override, optional startup probe (cheap json_schema + context ping). Capability is **not** inferred
  from the wire shape.
- **Structured output**: `generate_structured(client, messages, schema, descriptor)` picks the
  highest tier the descriptor supports, always finishing with `pydantic` validation + ≤N re-asks
  feeding the validation error back.
- **Fallback**: `RoleRouter` holds an ordered binding list per role; on hard failure / capability
  mismatch advance to next; publish `EventType.LLM_FALLBACK`. Fail over only before first token.

**Refactor**: `ReasoningModule` takes a `RoleRouter` (or a `ChatClient` for a role) instead of the
concrete `OllamaLLMClient`. Existing `modules/reasoning/llm/client.py` `OllamaLLMClient` becomes a
thin shim over `OpenAICompatAdapter` (or is replaced; keep `ChatMessage` shape compatible). The
memory `Embedder` Protocol is unified with `interfaces/embedding.py` (one `Embedder`).

**Provider-agnostic everywhere**: nothing above the adapter imports a provider SDK; the `Reasoner`,
`MemoryModule`, and the future `LearningStrategy` all depend on roles/seams.

## B. Privacy foundation

```
morgan_brain/privacy/
  classification.py  DataClass(PUBLIC|PERSONAL|SENSITIVE|SECRET); classify(text/metadata) heuristics + explicit tags
  redaction.py       EgressRedactor: regex (email/phone/card/key/IP) -> optional Presidio NER (lazy) -> deterministic «TOKEN_NNN»; rehydrate(response) (streaming-aware buffer)
  crypto.py          Argon2id KEK from passphrase; envelope DEKs (AES-256-GCM); seal()/open() for field-level encryption
  store.py           SQLCipher connection helper (keyed SQLite) for the temporal/profile stores
  egress.py          EgressGate: wraps a ChatClient; for a REMOTE binding, redact outbound messages + rehydrate stream; for LOCAL binding, pass through; hard-block SECRET tier from any prompt and from the vector store
```

- The **provider layer is the single egress chokepoint** — `EgressGate` decorates remote `ChatClient`s.
  Local providers (Ollama/vLLM/llama.cpp/LM Studio) get full context; remote gets redacted only.
- `crypto`/`store` are wired into the temporal fact store + workspace; Qdrant sensitive payload fields
  sealed before insert, opened after retrieval.
- A **redaction completeness test** (incl. non-English names → known NER gap) lives in the eval dir.
- Privacy is **opt-in by config** for the single owner now (`MORGAN_ENCRYPTION`, `MORGAN_REDACT_EGRESS`)
  but the seams exist so it's a flag flip, not a refactor.

## C. Future-proofing + MLflow scaffold

- **`schema_version`**: add `schema_version: int = 1` to `interfaces/events.py` `Event`; document the
  additive-optional rule; add a tiny CI test asserting every `Event` subclass declares one and that
  the enum/event registry is stable (schema-drift guard).
- **MLflow seam**: `morgan_brain/learning_lifecycle/` with `Optimizer` + `Registry` Protocols and an
  `mlflow_*` implementation (lazy import; `MLFLOW_DISABLE_TELEMETRY`/`DO_NOT_TRACK` forced on; tracking
  uri `sqlite:///./data/mlflow.db`). Phase 0.5 ships the seam + a no-op/local backend + config; the
  real GEPA optimize + evaluate land in Wave 1/5. `mlflow-tracing` slim is an optional extra, wired in
  the service layer behind a flag.

## Config additions (`MORGAN_`)
`MODELS` (path to capability/binding YAML) · `PROVIDERS` (per-provider base_url/api_key) ·
`ROLE_BINDINGS` (role→[provider:model]) · `ENCRYPTION` (bool) · `PASSPHRASE` (or keyring ref) ·
`REDACT_EGRESS` (bool) · `MLFLOW_TRACKING_URI` · feature flags per provider/adapter.

## Testing
Unit per module with fakes (no network): wire types, capability gating, router selection + fallback,
structured-output ladder (tier selection + re-ask), redaction round-trip (redact→rehydrate exact),
classification, crypto seal/open, schema_version guard. Integration: `Reasoner` over `RoleRouter`
with `FakeChatClient` still passes the Phase-1 chat loop. Provider adapters are smoke-tested against
live endpoints separately (not in unit CI).

## Non-goals (deferred)
Real MCP/agent platform (Phase 3), Cedar policy engine (Phase 3), Firecracker/WASI isolation
(Phase 3), full GEPA optimize/evaluate runs (Wave 1/5), remote gateway/Tailscale (Phase 5),
semantic routing, sidecar gateway for exotic remote providers.

## Increment order & DoD
A → B → C, each on the wave branch, each ending green (pytest + ruff + mypy-strict) and leaving the
Phase-1 chat loop working. Wave 1 (Phase 2) starts only after A at minimum (it needs the
provider-agnostic `strong`/`reflection` roles).
